# AXF-138 — Apply the Forecasting Policy v1.0.0 to the scenario comparison

Applies `AXF-FORECASTING@1.0.0` to the result of the sibling engine (`ALT_CLS_ForecastComparisonService`,
AXF-137). It does not recompute horizons or scenarios; it classifies, ranks and gates what that
engine assembles.

## Policy clauses applied

| Clause                                                              | Where                                                                                                                                                                              |
| ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §2 evidence precedence, ranked, without duplication                 | `AUTHORITY_*`; `classifyOccurrence`; `SourceView.resolvedOverlapCount` (ranked and deduplicated; the replacement rule itself is **not** implemented — see the open AC-1 gap below) |
| §3 category taxonomy and the method v1.0.0 permits per class        | `CATEGORY_*`, `METHOD_*`; `classifyOccurrence`; the standalone `CategoryView` per contribution                                                                                     |
| §3 fallback column, as actually applied                             | `FALLBACK_*`; `Result.fallbacks`                                                                                                                                                   |
| §5 identity, taxonomy, authority, cutoff, inclusions/exclusions, FX | `Result.policyVersion`, `Result.categoryTaxonomy`, `Result.categories`, `Result.asOf`, `Result.sources`/`exclusions`, `Result.currencies`                                          |
| §5 states `INFORMATIVE` / `DEGRADED` / `BLOCKED`                    | unchanged derivation of AXF-137; the class without a method gates by material impact (`blocked` when the omission could raise capacity)                                            |

## Rules

- **Every contribution carries its class and authority.** A schedule occurrence is contractual /
  installment (`INSTALLMENT`, `PRICE`, `SAC`) at authority 2, or a fixed recurrence (`RECURRING`) at
  authority 4; its amount is used exactly as declared, so no recurrence and no amount is invented.
  An occurrence the policy gives no method to carries **no** authority: none was established, and
  `AUTHORITY_APPROVED_RECURRENCE` would assert an approved recurrence that the evidence never
  showed. A standalone `FinancialTransaction` with an explicit amount, period, currency and state is
  an explicit scenario item (integral scenario inclusion) at authority 1 when it is a confirmed
  fact and at authority 5 otherwise.
- **§2 rank 3 is not assembled here.** Approved WorkRecords and billing schedules are not an
  evidence source of this engine (AXF-137 scope), so no contribution carries authority 3 and no
  constant is declared for it. Rank 6 (statistical estimation) is named by no approved policy
  version, so no contribution may carry it.
- **Overlapping evidence is resolved once.** A persisted occurrence is the projection's own row of
  its schedule; the standalone scenario query never reads it again. `resolvedOverlapCount` reports,
  per schedule, how many occurrences the schedule's evidence replaced, so the resolution is
  observable instead of implicit in a query predicate.
- **§2 cross-source precedence is NOT implemented — open AC-1 gap.** What is implemented is
  deduplication: each occurrence is counted exactly once, and the rank of each contribution's
  source is recorded (`authority`). What is **not** implemented is §2's "higher-authority evidence
  replaces the overlapping lower-authority contribution": the engine does not compare a contract
  schedule, an approved recurrence and an explicit scenario `CashFlow` that cover the same
  period/category and drop the lower-ranked amounts. Today such overlapping sources are summed at
  their own authority. No half-built replacement rule is in place; implementing it properly (which
  requires a period/category key for evidence and an approved category catalog) belongs to a
  follow-up slice, and this gap must not be read as satisfied by the `authority` field.
- **A class with no method is never estimated.** The class of a scheduled occurrence comes from the
  applied policy's own category → method table (§3), read over the method that produced its amounts:
  `INSTALLMENT`/`PRICE`/`SAC` are row 1 (contractual/installment, `authoritative-schedule@1.0.0`,
  authority 2) and `RECURRING` is row 3 (fixed recurrence, `approved-recurrence-schedule@1.0.0`,
  authority 4, the declared amount used as declared). Every other method — `ESTIMATED`, whose
  amount comes from a reference value instead of the approved formula, and any method the policy
  does not name — is row 5, for which v1.0.0 approves no method. The class is **not** read from
  `AXF_SDF_TXT_FormulaVersion__c`: `ALT_CLS_FinancialScheduleService` stamps the amortization
  policy version on every definition alike, so an equality test against it can only distinguish
  hand-crafted rows and turns every comparison `BLOCKED` if the version is ever bumped. For row 5
  no tier, amount, average, weight or probability is asserted: the occurrence is reported with
  `NO_APPROVED_METHOD`, its class, the fallback of its row, no authority (none was established)
  and an exclusion of its holder.
- **An omission is recorded, never silent.** An occurrence the policy gives no method to — and one
  whose definition cannot be read, whose class is therefore not established either — is dropped
  from the totals **and** recorded as an `Exclusion` for its holder with reason `NO_APPROVED_METHOD`,
  so an incomplete total is distinguishable from a complete one and reconciles. This is the reading
  chosen for the conservative branch a null definition used to have: it is recorded explicitly
  rather than restored as a summed `PROBABLE` line, because summing it would assert a tier for
  evidence whose class and authority were never established. `Exclusion` entries are deduplicated
  per holder and reason, so a schedule of hundreds of occurrences does not flood the explanation.
- **`contributionCount` counts contributions, not occurrences.** The §3 class row is created where
  an occurrence is classified, but its count is incremented only where a contribution is actually
  added: an occurrence dropped for having no approved method, and one dropped by the
  `INCOMPLETE_CONTRIBUTION` filter, never inflate it.
- **The gate follows material impact.** Omitting an obligation could increase the capacity shown, so
  an omission is display-only (`INFORMATIVE_DISPLAY`) only when it cannot: an inflow. Any other
  direction is `BLOCKED_MATERIAL_OMISSION` and the result is `BLOCKED` with the class visible.
- **The new reason reaches the UI as a label.** `NO_APPROVED_METHOD` is mapped in
  `aXF_LWC_forecastComparison` so the explanation renders a label instead of the raw server code;
  the component still renders only what the server returned and computes no state.

## Ambiguities and judgement calls

- **"Authority" is read as §2 evidence precedence**, per `6520833.md:35` ("Higher-authority evidence
  replaces the overlapping lower-authority contribution; it does not add to it") and the limitation
  AXF-144 recorded for the confidence panel. It is not the policy identifier.
- **"Persists" is read as "records on the result."** No CalculationSnapshot exists in this engine and
  the story's scope is the comparison result; the snapshot contract belongs to AXF-23.
- **"Cutoff" is `asOf`** — the instant up to which evidence was considered — following the same
  reading AXF-144 recorded. **"FX" is the preserved original currency set** (`Result.currencies`):
  this engine converts nothing, so no rate is consumed and no report-currency value exists that
  could be missing. `PENDING_FX|BLOCKED` therefore cannot arise here; it belongs to §5 and to the
  story that introduces report-currency conversion.
- **§3's classes are read as the classes of the evidence this engine assembles.** The
  taxonomy is mapped from the definition method, not from `AXF_FTX_TXT_UserCategory__c`, which is
  free text with no catalog yet ("até AXF-30 fixar catálogo") — mapping arbitrary user text to a
  policy class would be the invented taxonomy the policy forbids.
- **The class v1.0.0 gives no method to is reached through the policy's own method table.** The
  reachable case is the `ESTIMATED` schedule method: its amounts come from a reference value rather
  than from the approved amortization formula (`AXF_SDF_PKL_Method__c` = "Estimado por referência";
  the command writes no modality for it), which is exactly §2 rank 6 — statistical/estimated
  evidence for which no approved policy version names a method — and therefore §3 row 5. No local
  threshold, weight or default method was introduced. **Consequence, stated plainly:** an indefinite
  recurrence is only expressible as `ESTIMATED` in this system (a calculated method requires a
  finite installment count), so an indefinite recurring commitment is now reported, excluded and
  `BLOCKED` when omitting it could raise capacity, instead of contributing a `DEGRADED` total. That
  is the fail-closed direction §3 row 5 and §3's "uncertainty may not increase spendable or
  investable capacity" demand; if the policy is later read as approving a reference-based
  recurrence, the change is one row of `RECURRENCE_METHODS`.
- **The conservative null-definition branch is recorded, not restored.** AXF-137 summed a line with
  no resolvable definition as `PROBABLE`; this change replaces that with an explicit exclusion
  (`NO_APPROVED_METHOD`) plus the material gate, so an obligation is never dropped in silence and no
  tier is asserted for evidence whose class was never established.
- **Two AXF-137 expectations moved with the applied policy, and were not weakened.** The fixtures of
  `scenariosIncludeTiersIntegrallyAndOverdueStaysVisible` and
  `multiCurrencyUnboundedFloorAndPlanCeilingAreExplicit` use `ESTIMATED` schedules; their assertions
  that those occurrences were summed as `PROBABLE` (and that an indefinite one left the result
  `DEGRADED`) are now the opposite, plus new assertions that the omission is explained, excluded and
  gated. Every other assertion of both tests is unchanged, and the `DEGRADED` state is still
  covered by the partial-access test.
