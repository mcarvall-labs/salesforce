# AXF-138 — Apply the Forecasting Policy v1.0.0 to the scenario comparison

Applies `AXF-FORECASTING@1.0.0` to the result of the sibling engine (`ALT_CLS_ForecastComparisonService`,
AXF-137). It does not recompute horizons or scenarios; it classifies, ranks and gates what that
engine assembles.

## Policy clauses applied

| Clause                                                              | Where                                                                                                                                     |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| §2 evidence precedence, ranked, without duplication                 | `AUTHORITY_*`; `classifyOccurrence`; `SourceView.resolvedOverlapCount`                                                                    |
| §3 category taxonomy and the method v1.0.0 permits per class        | `CATEGORY_*`, `METHOD_*`; `classifyOccurrence`; the standalone `CategoryView` per contribution                                            |
| §3 fallback column, as actually applied                             | `FALLBACK_*`; `Result.fallbacks`                                                                                                          |
| §5 identity, taxonomy, authority, cutoff, inclusions/exclusions, FX | `Result.policyVersion`, `Result.categoryTaxonomy`, `Result.categories`, `Result.asOf`, `Result.sources`/`exclusions`, `Result.currencies` |
| §5 states `INFORMATIVE` / `DEGRADED` / `BLOCKED`                    | unchanged derivation of AXF-137; the class without a method gates by material impact (`blocked` when the omission could raise capacity)   |

## Rules

- **Every contribution carries its class and authority.** A schedule occurrence is contractual /
  installment (`INSTALLMENT`, `PRICE`, `SAC`) at authority 2, or a fixed recurrence (`RECURRING`,
  `ESTIMATED`) at authority 4; its amount is used exactly as declared, so no recurrence and no
  amount is invented. A standalone `FinancialTransaction` with an explicit amount, period, currency
  and state is an explicit scenario item (integral scenario inclusion) at authority 1 when it is a
  confirmed fact and at authority 5 otherwise.
- **§2 rank 3 is not assembled here.** Approved WorkRecords and billing schedules are not an
  evidence source of this engine (AXF-137 scope), so no contribution carries authority 3 and no
  constant is declared for it. Rank 6 (statistical estimation) is named by no approved policy
  version, so no contribution may carry it.
- **Overlapping evidence is resolved once.** A persisted occurrence is the projection's own row of
  its schedule; the standalone scenario query never reads it again. `resolvedOverlapCount` reports,
  per schedule, how many occurrences the schedule's evidence replaced, so the resolution is
  observable instead of implicit in a query predicate.
- **A class with no method is never estimated.** When the definition that produced an occurrence's
  amounts records no authority the policy permits (`AXF_SDF_TXT_FormulaVersion__c` — "which
  authority produced the calculated values" — is not `AMORT-POLICY@1.0.0`), or when the occurrence
  belongs to no class the policy names, v1.0.0 approves no method. No tier, amount, average, weight
  or probability is asserted for it: the occurrence is reported with `NO_APPROVED_METHOD`, its class
  and the fallback of its row.
- **The gate follows material impact.** Omitting an obligation could increase the capacity shown, so
  an omission is display-only (`INFORMATIVE_DISPLAY`) only when it cannot: an inflow. Any other
  direction is `BLOCKED_MATERIAL_OMISSION` and the result is `BLOCKED` with the class visible.
- **The new reason reaches the UI as a label.** `NO_APPROVED_METHOD` is mapped in
  `aXF_LWC_forecastComparison` so the explanation renders a label instead of the raw server code;
  the component still renders only what the server returned and computes no state.

## Ambiguities and judgement calls

- **"Authority" is read as §2 evidence precedence**, per `6520833.md:35` ("Higher-authority evidence
  replaces the overlapping lower-authority contribution; it does not add to it") and the limitation
  AXF-144 recorded for the confidence panel. It is not the policy identifier.
- **"Persists" is read as "records on the result."** No CalculationSnapshot exists in this engine and
  the story's scope is the comparison result; the snapshot contract belongs to AXF-23.
- **"Cutoff" is `asOf`** — the instant up to which evidence was considered — following the same
  reading AXF-144 recorded. **"FX" is the preserved original currency set** (`Result.currencies`):
  this engine converts nothing, so no rate is consumed and no report-currency value exists that
  could be missing. `PENDING_FX|BLOCKED` therefore cannot arise here; it belongs to §5 and to the
  story that introduces report-currency conversion.
- **§3's classes are read as the classes of the evidence this engine assembles.** The
  taxonomy is mapped from the definition method, not from `AXF_FTX_TXT_UserCategory__c`, which is
  free text with no catalog yet ("até AXF-30 fixar catálogo") — mapping arbitrary user text to a
  policy class would be the invented taxonomy the policy forbids.
- **The class v1.0.0 gives no method to is reached through the recorded formula authority.** A
  schedule whose computed amounts were produced by no authority the policy permits is the reachable
  case of "no method"; the policy's named classes (variable, seasonal, discretionary, exceptional)
  are the classes of that same row. No local threshold, weight or default method was introduced.
