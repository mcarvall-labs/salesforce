# AXF-141 — Reverse a reconciliation with a compensating allocation and safe replay

Simple-reversal slice of AXF-31 under `AXF-REVERSAL@1.0.0`, built on the AXF-25 compensation contract (`ALT_CLS_RealizationService.reverse`).

## Components

| Component                                                                                                      | Role                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_CLS_RealizationService.reverse(allocationId, expectedVersion, operationKey, reasonCode, reasonNote)`      | New overload: the reason travels with the compensation and with its payload fingerprint. The 3-argument overload delegates with null reasons and keeps pre-existing fingerprints replayable.                                              |
| `AXF_OBJ_ReconciliationAllocation__c.AXF_RA_PKL_ReversalReason__c` / `AXF_RA_TXT_ReversalNote__c`              | Reason (USER_ERROR, DUPLICATE_LINK, WRONG_TARGET, SOURCE_CHANGED, OTHER) and note (≤ 255) on the REVERSAL row; immutable through the existing realization guard; FLS in `AXF_PS_Realization`.                                             |

Capability `AXF_CanReverseReconciliation` (+ `AXF_CanRealize`) in `AXF_PS_GestorFinanceiro`.                                                  |

## Rules

- **Compensation, not edition**: reversing appends one immutable `REVERSAL` allocation linked to the original (`AXF_RA_LKP_OriginalAllocation__c`), same magnitude/currency/source/target, with the reason. Original allocation, source fact and plan content stay untouched; only optimistic versions move (AXF-25). Updates and deletes of any allocation outside the service are rejected by the trigger guard.
- **Derived net**: after the command the plan is re-read through AXF-25 `read` (planned / realized / residual / state / version) and the source residual is recomputed from visible effects; both are returned so the caller sees the restored contribution.
- **Reason contract lives in AXF-25**: `ALT_CLS_RealizationService.REVERSAL_REASONS` validates the code (`INVALID_REASON`), a note never travels without a code (`INVALID`), the note is trimmed before the 255 bound, `expectedVersion` is required (`INVALID`, never a silent `CONFLICT`). The wrapper runs compensation and derived-state read under one savepoint: a caller that catches the exception never keeps a compensation whose result it did not receive.
- **Replay and conflict**: same operation key + same payload (allocation, expected version, reason, note) → prior compensation (`replayed = true`); same key with a different reason/note/version → `CONFLICT`; a different key on an already reversed allocation → `ALREADY_REVERSED` (no second compensation; `priorReversal` exposes the existing one). Reversing a `REVERSAL` → `INVALID_TARGET` (direct AXF-25 callers get `INVALID` for the same condition). Stale plan version → `CONFLICT`. Two concurrent reversals of the same allocation: the one that loses the AXF-25 lock answers `CONFLICT`; the UI then reloads the list and shows the prior compensation on `ALREADY_REVERSED`.
- **ACTUAL_ONLY**: the plan born from a fact keeps its role and magnitude as history; after reversal `plannedAfter = 0`, `residualAfter = 0`, `stateAfter = NONE` — no forecast debt is invented and no PLANNED transaction is created. Consumer rule: the realized state of any plan is what AXF-25 `read` derives from its allocations; the FTX magnitude alone is never "realized".
- **Source remaining** in the result is computed from the effects visible to the user and labelled so; a read that reaches `MAX_ALLOCATION_ROWS` leaves it unknown instead of over-reporting.
- **Boundary (AXF-104)**: targets that are schedule occurrences (`AXF_FTX_LKP_Schedule__c`) are reversed like any other, and the result carries `AXF104_OBLIGATION_ADJUSTMENT_PENDING`. Obligation adjustments and recurring-reference recomputation are not performed here; they belong to the AXF-104 contract (not yet in `develop`) and to the composite reversal (AXF-142).
- **Fail closed**: capability missing, foreign holder or invisible allocation → `UNAVAILABLE`; errors are sanitized `{code}` values.

## Validation

- AXON_DEV: `ALT_CLS_ReconciliationReversalTest` 5/5 (service 95 %, controller 85 %): compensation with reason and trimmed note, plan realized 0 / residual 100, source residual 100, versions bumped, replay, CONFLICT on divergent reason and note, `ALREADY_REVERSED`, `priorReversal`, immutability (update/delete rejected), listing shows the reversal; ACTUAL_ONLY reversal with zero residual and no PLANNED row; guards (capability, foreign holder, reason, note length, key, stale version, strict JSON, reversal as target). `ALT_CLS_RealizationServiceTest` 16/16 still green (98 %) and now pins the legacy fingerprint, the cross-overload `CONFLICT`, `INVALID_REASON` and note-without-reason.
- Also covered after code review: CARD and CASH sources, two applications on one fact (source remaining 70 after reversing 60), schedule-occurrence boundary, `targetVersion` from the listing, holders in the context, pagination and OFFSET ceiling, `expectedVersion` required, note trimmed before validation; Jest: prior compensation on `ALREADY_REVERSED`, list reload on `CONFLICT`, null-safe derived state.
- Jest 3/3; ESLint clean.
