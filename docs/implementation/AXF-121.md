# AXF-121 — Non-resurrection invariant on restore

Implements the restore/rollback slice of AXF-9. The backup vendor and mechanism are `Deferred`
(G9-3, tracked in AXF-79), so this delivers the **invariant** and the integration point a restore
must respect — not a restore.

The story itself (`AXF-121`) states the scope: the vendor/mechanism is `Deferred`, this story
implements the invariant — **non-reactivation marking plus minimal evidence preserved** — and a
simulated-adapter test does not substitute for a real restore.

## Components

| Component                                                  | Role                                                                                                                      |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `AXF_OBJ_ClosureRun__c.AXF_CLR_TAL_NonReactivationMark__c` | The mark: written once, with the terminal state, and frozen afterwards by the closure's `CLOSED` immutability rule.       |
| `ALT_CLS_RestoreInvariant`                                 | Builds the mark (write path) and answers, per restored scope, whether reactivation is permitted (read path, fail-closed). |
| `ALT_CLS_ClosureOrchestrator`                              | `RETAIN_EVIDENCE` writes the mark in the same update that sets `CLOSED` — the closure marks what cannot be reactivated.   |
| `ALT_CLS_RestoreInvariantTest`                             | Acceptance coverage for the AC, including the negative case.                                                              |

No new object, no new acronym: the mark reuses the closure run that already is the scope's private,
non-deletable, terminal-immutable lifecycle record. The mark's key set is what makes it safe to
keep: `schemaVersion`, `scopeKey`, `correlationId`, `policyVersion`, `closedAt`, `fingerprint`.

## Acceptance criteria

1. **Given** a later restore or rollback, **when** deleted/pseudonymised data is found in a backup,
   **then** it is not reactivated in the active service.
   `assess(holders)` returns `NOT_REACTIVATED` for any scope with a known closure lifecycle, and the
   guard performs no reactivation itself: the restored source stays in custody and collection stays
   paused.
2. **And** minimal evidence preserves the proof of the lifecycle without reconstructing private
   content. The mark carries only the allowlisted keys, digested with SHA-256 over exactly those
   fields; the digest is what makes a spliced or altered mark detectable, and a key outside the
   allowlist is refused outright. The class never reads a content field, so nothing private can
   reach the proof.
3. **Fail-closed defaults (AD-24).** Refusal is the safe answer for a closure still running, for a
   `CLOSED` run whose mark was never written (any closure that reached `CLOSED` before AXF-121
   shipped), for a mark belonging to another scope, and for an altered mark. Only a scope with no
   closure lifecycle at all is allowed to reactivate.

## Authorization

The entry point requires the closure capability `AXF_CanCloseInstallation` (reused from
`ALT_CLS_ClosureOrchestrator.CP_CLOSE`, single source of truth) and throws `FORBIDDEN` otherwise.
The lifecycle read is deliberately `WITH SYSTEM_MODE`: the invariant is a protection duty, not a
record-visibility question, and a caller who cannot see a closure must never be answered "allowed".
Only content-free fields are read, and the caller only ever learns about scopes it already named.

## Known boundary (stays open in AXF-79)

The mark lives inside the same database as the data it protects. A restore that also rolls back the
closure evidence is therefore outside the reach of this build; the deferred mechanism must guarantee
that the closure evidence outlives, or is reasserted after, the restored window. This is exactly why
a real restore rehearsal — not a simulated adapter — remains a production gate (AD-18, G9-6 item 4).
