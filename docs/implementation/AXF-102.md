## Round 2 (after code review, 2026-09-15)

`contentHash` originally hashed `String.valueOf(magnitude)`: the hot fields are scale 2 and the
archive field is scale 8, so every real verification would have failed (`PARITY_MISMATCH`). The
hash now normalises to `setScale(8).toPlainString()` and renders the day with `formatGmt`.
Re-run on the real store with the hash written before insert and recomputed after read-back:

```
SPIKE2 insert=7/7 pages=3 read=7 distinct=7 hashRoundTrip=7/7 readBackMagnitude=14.50000000
SPIKE2 cleanup left=0
```

Also confirmed: non-index big-object fields are invisible to a user without FLS on them (even
`SObject.put` fails), so the writer needs the field grants that `AXF_PS_GestorFinanceiro` carries;
reads in `ALT_CLS_ArchiveStore` use `WITH SYSTEM_MODE`.

## Accepted design (implemented in AXF-95, PR on `feature/AXF-95-big-object-archive`)

- Source families: BAT / CCT / FTX (no `FinancialEntry`). Mapping in
  `ALT_CLS_ArchiveRunService.toArchiveRow`: original magnitude/direction/currency/status/
  description, source identity (`SourceKey` / `ClientRequestId`), canonical institution id
  (`AXF_BA/CC_LKP_BankInstitution__c`) plus the historical label (AXF-106), policy version, run
  key, content hash and a JSON snapshot of the hot row.
- Archive identity: `ArchiveKey = SHA-256(family|sourceKey)` — the record id is never the
  identity, so a re-imported fact archives to the same row.
- Run state: `AXF_OBJ_ArchiveRun__c` (private checkpoint): family, holder, policy version,
  hot-window start, watermark (last day written), counts, per-currency amounts, chained hash,
  phase `SCANNING → WRITING → VERIFYING → HOT_RETAINED | FAILED`, `HotRemoval = BLOCKED:<reason>`.
- Authorization: `AXF_CanReadArchive` + holder visible with an Axon record type, checked when the
  request arrives and again before rows are returned; every returned row is keyed to that holder.
  `AXF_CanArchiveTransactions` + full access (`UserRecordAccess.HasAllAccess`) to start a run.
- Hot-copy removal: never executed; verified runs end `HOT_RETAINED` with
  `BLOCKED:HOT_REMOVAL_NOT_AUTHORIZED` (or `BLOCKED:RECOVERY_GATE_OPEN` when the policy flag is
  on) until the AXF-79 recovery/cutover gate and Michel's explicit authorization exist.
