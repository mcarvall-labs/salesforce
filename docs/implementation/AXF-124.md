## Judgement calls

- **Any context change invalidates, not only the ones that name the same scope.** Both components
  have their own scope input, and neither is bound to the context bar's selection. Binding them
  would be a contract nobody ratified; treating the announcement as what the channel says it is — a
  reason to clear and refetch — is the ratified reading and the only one that satisfies "data from
  the previous context does not remain". A re-derivation of an unrelated scope returns the same
  answer, so nothing is lost by revalidating.
- **The event payload is not consumed.** `changeReason` does not change what has to happen (total
  discard + revalidation for both reasons), so reading it without a behavioural difference would be
  a flag that never varies; `selectionVersion` would only matter for a duplicate or out-of-order
  announcement, which the publisher cannot produce (it publishes once per transition). Acting on
  `accountId`/`presentationCurrency` would mean adopting the bar's selection or applying a
  presentation currency — both outside the declared scope (presentation is AXF-125, conversion is
  AXF-123) and neither ratified for these components.
- **No new server "revalidate" method.** Revalidation is the existing `explain` / `compare` / (for
  AXF-122) `consolidate` call: they read effective access on every invocation. A parallel method
  would be new machinery for a behavior that is already proven by test.
- **The announcement is cleared, not replaced.** No new Custom Label was created and no
  `translations/` container was deployed: the pendencies record that deploying the translation
  container on the shared `AXON_DEV` can wipe another line of work's `AXF_AccessLevel_*` labels, and
  the loading state of both components already announces itself (`lightning-spinner` alternative
  text, inside a `role="status"` region in the confidence panel). Clearing is what the AC requires;
  inventing a new string was not required.
- **`requestToken` is bumped in both handlers.** `load()` also bumps it, so the handler's bump only
  matters where the handler issues no call — the record page and, more importantly, the arm where the
  scope is empty. Without it, a comparison in flight when the bar revalidates on focus lands
  afterwards and re-renders the previous context's totals; that case is pinned by its own test.
- **Unsubscribe in `disconnectedCallback`,** following the listener discipline of
  `aXF_LWC_contextBar.js:47-54`, so a navigation does not leave a live subscription behind.
- **A failed holder refresh is surfaced by the wire itself.** `refreshApex` rejection is delivered to
  the wired function's error branch, which renders the sanitized error and the retry; the empty
  `.catch` only avoids an unhandled rejection. No second error surface was added.

## AXF-32 is still open — what that restricts

AXF-32 ("Confirmar uma transferência interna") is **not delivered**: `AXF_OBJ_InternalTransfer__c`
and its neutrality key do not exist in this branch. It is a predecessor listed by the story, and
the pendency **P2** asked whether it is a real prerequisite.

**It is not.** Neither acceptance criterion here mentions internal transfers, and this pass adds no
contribution, allocation or normalization rule of its own: it discards a derived result and asks the
existing servers to derive it again. Nothing in the delta reads, composes or assumes the internal
composition of a fact's contribution, so it cannot be affected by whether a transfer pair is
recognized. AXF-135 already refuses `TRANSFER`/`REFUND` link roles without writing, and the
neutralization of a transfer pair is declared as AXF-32's own contract by AXF-129 — that stays
untouched. **What it restricts:** none of the two criteria above; the delivery is complete without
AXF-32. What it defers is only that, once AXF-32 lands, a transfer pair's neutralization will be
recomputed by this same discard-and-re-derive path, which needs no change here.

## Limitations and declared gaps

1. **The presentation-currency change has no cross-component event.** AC (a) names "moeda". A change
   of the _holder context_ carries `presentationCurrency` and is therefore covered, and a scenario or
   horizon change inside the comparison component already re-derives. But a change made in
   `aXF_LWC_reportCurrencyPreference` publishes nothing: `AXF_ContextChanged` is the only message
   channel in the repository and that component does not use it. Covering that would need a new or
   extended message channel — metadata whose form is not ratified — so **nothing was invented**;
   the gap is declared and needs a decision.
2. **The AXF-122 consolidated KPI surface has no runtime surface.** `ALT_CLS_ConsolidationService`
   is reachable only from Apex and tests (no controller, no LWC — presentation is AXF-125), so its
   part of both criteria is proven by Apex test and not by a browser surface.
3. **Provider-level consent revocation still contributes.** The confidence panel reports
   `CONSENT_REVOKED` / `CONSENT_STALE` as an exception on the row but keeps the source included, and
   the consolidation totals read sources by holder without consulting the connection's consent
   state. Read literally, AC (b) — "remove the contribution without remaining legitimate access" —
   is not satisfied at the provider level, and "expiração" is not exercised as its own case. That is
   the scope of **AXF-120** ("Tratar estados bloqueados e revogação externa Pluggy", not delivered),
   and nothing here changes it. What _is_ exercised is the access loss through which revocation and
   expiry both manifest in the native model.
4. **A revocation landing while a server request is in flight is not reproducible** in one Apex
   transaction (sharing is fixed when the transaction starts), so that half is proven on the client
   (the late answer never lands) and not on the server.
5. **Other holder-scoped surfaces keep a cached holder list and do not subscribe to the channel:**
   `aXF_LWC_archiveExplorer.js:43,72`, `aXF_LWC_reconciliationReversal.js:19,36`,
   `aXF_LWC_sourceLink.js:165,193` and the holder getters of `aXF_LWC_closureRun` /
   `aXF_LWC_economicAllocation`. They were **not** changed: the story's scope is the consolidated
   recalculation, and clearing a wizard's input mid-flow needs a product decision of its own (a
   silently dropped selection could be worse than a stale option). Declared for the next decision.
6. **No layout mounts the publisher together with a subscriber.** `AXF_HomePage.flexipage-meta.xml`
