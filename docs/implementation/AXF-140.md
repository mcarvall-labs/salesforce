# AXF-140 — Ties, uncertainty and partial / multi-currency candidates

Edge-case slice of AXF-29 under `AXF-MATCHING@1.0.0`, stacked on AXF-139
(`ALT_CLS_MatchEvidence`, `ALT_CLS_SourceLinkService`). It consumes the candidate presentation of the
sibling story; it does not rebuild it.

## Components

| Component                             | Role                                                                                                                                                                                                                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_CLS_MatchEvidence` (AXF-139)     | Consumes the canonical blocked state (`STATE_BLOCKED`, policy §3) and gains withheld-evidence handling: a redacted identity carries no value and never satisfies `EXACT`, so it cannot order.                                                                                                      |
| `ALT_CLS_SourceLinkService` (AXF-134) | Candidates in another currency are listed with their facts kept apart (`amount` original, `residual` available, `currencyIso`, `conversion`, `residualAfter`), stay `BLOCKED` and are never selectable. Confirmation of a pair without material FX evidence is refused with `MISSING_MATERIAL_FX`. |
| `aXF_LWC_sourceLink` (AXF-134)        | Renders the server state instead of a hardcoded consultative badge, the conversion evidence line and the remaining residual (`Remaining after: 0.01 BRL`). A blocked candidate shows no draft allocation action.                                                                                   |

## Rules

- **No tolerance, weight, default rate or conclusion policy is introduced.** Policy v1.0.0 approves
  none, so nothing here invents a number: a remainder of `0.01` is reported as `0.01`, and ordering
  stays the presentation order of AXF-139 (never a score).
- **Partial means explicit.** `residualAfter` is the remainder left on the candidate once the
  source's available amount is applied to it (same currency): `available − min(source available,
available)`. It is reported as computed, never zeroed, and the candidate stays `CONSULTATIVE`
  (policy §3: candidates remain consultative until the user constructs allocations).
- **Another currency is a blocked candidate, not a hidden one.** The candidate is shown — with the
  original amount, the original currency and the conversion evidence of the approved indicative
  layer (AXF-92 vocabulary `ESTIMATED` / `STALE` / `UNAVAILABLE`, its `QUOTE_MAX_AGE_DAYS` and
  `PROVIDER_BCB_PTAX` constants, one read per page) — because completion requires exact currency
  arithmetic (policy §3) and eligibility requires material FX evidence when currencies differ
  (policy §2). `linkable` stays false and the reason is named.
- **A missing material rate blocks confirmation.** `confirm` checks the material rate before the
  currency contract, so the refusal names what the user must correct (`MISSING_MATERIAL_FX`) when no
  fresh quote exists for the pair; with a usable quote the refusal remains `CURRENCY_MISMATCH`.
  `AXF-25` still enforces exact currency, so a rate never turns a mismatch into an allocation.
- **Withheld evidence neither appears nor orders.** The provider key is never disclosed to the client
  (`SourceView.sourceKey` is transientso), so the assembly reports `EXTERNAL_IDENTITY` as `REDACTED`
  with no values, and a redacted feature never marks a candidate for the presentation order (policy
  §2: redaction cannot contribute indirectly to ordering). Absent evidence stays `UNKNOWN`. The page
  keeps carrying `matchingPolicy` and `evidenceCutoff`, and confirmation stays the explicit human
  command of AXF-134.
- **Virtual projection lines stay same-currency.** They are projections of the holder's own schedule
  and are never linkable before materialization (AXF-136), so no conversion evidence is derived for
  them.

## Acceptance criteria mapping

| Criterion                                                                                             | Where                                                                                                                                          |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Unapproved tolerances/weights/conclusion stay consultative or blocked, no numbers                     | `ALT_CLS_MatchEvidence.STATE_BLOCKED`; `ALT_CLS_SourceLinkService.residualAfter`; `candidate()` currency block                                 |
| Partial / multi-currency candidate keeps original, available, currency, conversion and residual apart | `CandidateView` `amount` / `residual` / `currencyIso` / `conversion` / `residualAfter`; `resolveConversions`, `convert`, `indicativeQuotes`    |
| A missing material rate blocks confirmation                                                           | `candidate()` → `materialRate(...)` → `MISSING_MATERIAL_FX`                                                                                    |
| Absent evidence is `UNKNOWN`; withheld evidence does not appear or order                              | `ALT_CLS_MatchEvidence.identity(..., redacted)`; `side(SourceView).externalIdentityRedacted`                                                   |
| The decision stays human, explicit and auditable                                                      | unchanged AXF-134 confirmation; `matchingPolicy` + `evidenceCutoff` per page; the state and every fact are rendered, never derived client-side |

## Judgement calls and limits

- "Unavailable evidence" is read as evidence this workbench does not disclose: the provider key. It
  is therefore reported `REDACTED` and removed from ordering, which is a guarantee, not a behaviour
  change — candidates carry no external identity in v1, so the first ordering criterion was already
  inert.
- A currency-differing candidate is shown but `BLOCKED` even when a usable quote exists, because
  `ALT_CLS_RealizationService` refuses an allocation whose source and target currencies differ
  (`CURRENCY_MISMATCH`, policy §3 "exact currency arithmetic"). It is therefore never linkable; the
  quote is presentation evidence for comparison, and the reason is named. Reconciling across
  currencies would need a new approved policy and a realization contract for it.
- The indicative quote is read under sharing, not field-level security, exactly as the approved
  indicative layer does (AXF-92): the reference quote is shared data and its fields are not granted
  to every capability holder, so a field-level read would fail the whole workbench.
- No conclusion or completion state is persisted by this story. Recording the matching policy,
  cutoff, candidate identities and gate reasons on the confirmation belongs to AXF-30.
