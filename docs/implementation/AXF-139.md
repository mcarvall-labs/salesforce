# AXF-139 — Reconciliation candidates with observable evidence

Presentation slice of AXF-29 under `AXF-MATCHING@1.0.0`, stacked on AXF-134 (`ALT_CLS_SourceLinkService.listCandidates`).

## Components

| Component                             | Role                                                                                                                                                                                                                   |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_CLS_MatchEvidence`               | Pure, deterministic evidence: `evaluate(Side, Side)` → nine independent features, `signature` (tie detection), `lowEvidence`, `OrderKey` (policy presentation order). No SOQL, no weights, no tolerance, no score.     |
| `ALT_CLS_SourceLinkService` (AXF-134) | Every `CandidateView` carries `state = CONSULTATIVE`, `evidence`, `tied`, `lowEvidence`; the page carries `matchingPolicy`, `evidenceCutoff`, `tieCount`, `lowEvidenceCount`; ordering replaced by the policy order.   |
| `aXF_LWC_sourceLink` (AXF-134)        | Evidence column (one chip per feature with explanation and values on hover), consultative / tie / low-evidence badges, tie summary, presentation-order toggle (policy order or due date — client-side, deterministic). |

## Features and relations

| Feature             | Source side                                                                                                                                   | Candidate side                              | Relations                                                                                                                                                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `EXTERNAL_IDENTITY` | origin + provider key (disclosed with the fact: the caller is authorized for it, and the raw key still never travels as a `SourceView` field) | none in v1 (forecasts carry no external id) | `UNKNOWN` between a fact and a forecast; `REDACTED` only for a side the caller is not authorized for and therefore withholds; the first ordering criterion is inert until forecasts carry an external id |
| `SOURCE_IDENTITY`   | bank account / card of the fact                                                                                                               | expected funding of the forecast            | `EXACT` / `UNKNOWN`                                                                                                                                                                                      |
| `HOLDER`            | holder                                                                                                                                        | holder                                      | `EXACT` (both sides authorized by construction)                                                                                                                                                          |
| `CURRENCY`          | ISO                                                                                                                                           | ISO                                         | `EXACT`                                                                                                                                                                                                  |
| `AMOUNT`            | fact amount                                                                                                                                   | forecast amount                             | `EXACT` / `DIFFERENT` (+ signed delta)                                                                                                                                                                   |
| `RESIDUAL`          | fact remaining                                                                                                                                | forecast remaining                          | `EXACT` / `COVERS` / `PARTIAL` (+ delta)                                                                                                                                                                 |
| `DATE`              | fact date                                                                                                                                     | due date                                    | `EXACT` / `DIFFERENT` (`DATE_AFTER`/`DATE_BEFORE` + signed days)                                                                                                                                         |
| `DESCRIPTION`       | fact description                                                                                                                              | forecast description / schedule name        | `EXACT` / `CONTAINS` (`*_CONTAINS_CANDIDATE` / `*_CONTAINED_IN_CANDIDATE`, both sides ≥ 3 chars) / `DIFFERENT` / `UNKNOWN` / `REDACTED`                                                                  |
| `CATEGORY`          | provider category                                                                                                                             | user category                               | same as description                                                                                                                                                                                      |

Text comparison folds case, whitespace, punctuation and diacritics only — there is no fuzzy similarity. Missing evidence is `UNKNOWN` (never zero or negative) and carries no values. `REDACTED` is reserved for evidence the caller may not see: in v1 every field is read under `USER_MODE`, so an inaccessible field fails the request (`NOT_ACCESSIBLE`) instead of being redacted; the relation exists so a future cross-holder evaluation can withhold values without changing the contract. `HOLDER` is observed on each side (`AXF_FTX_LKP_Account__c` / `AXF_FSC_LKP_Account__c`), never copied. Virtual lines carry unknown funding and category (the active definition is not read in v1). Values are shown as stored (no rounding).

## Rules

- **Consultative**: every candidate and the page itself are `CONSULTATIVE`; the only way to reach confirmation is the explicit selection in AXF-134. No feature, tie-break or relation selects, pre-selects or confirms.
- **Ties and uncertainty are explicit**: candidates with identical relations **and identical exact deltas** on every feature are `tied` (counted in `tieCount`; a 1-day and a 300-day difference are never a tie); candidates with nothing `EXACT` beyond holder/currency are `lowEvidence` (counted). Neither changes what the user may do.
- **Order** (policy §2, presentation only): verified external identity, then exact source identity, then type rank (persisted before virtual), then record identity. The closest amount or date never leads. The UI can re-sort **the current page** by due date for reading (undated rows last; labelled "this page only"); the server order is the canonical one. Explanations are visible to assistive technology, deltas are signed, the cutoff is rendered in the user's locale. Policy text: Confluence "Matching Policy — Axon Finance" (page 6488065), mirrored in `docs/policies/MATCHING-POLICY.md`.
- **Cutoff and versioning**: `matchingPolicy = AXF-MATCHING@1.0.0` and `evidenceCutoff` (server time of evaluation) travel with every page.

## Validation

- AXON_DEV: `ALT_CLS_MatchEvidenceTest` 3/3 (94 %) — every feature independent with signed deltas, no tolerance; redaction/containment never expose values; policy ordering and tie signatures. `ALT_CLS_SourceLinkServiceTest` 8/8 re-run with the new order (service 95 %): funding-matched forecast first, then record identity; evidence on the real candidate (`SOURCE_IDENTITY`/`AMOUNT`/`RESIDUAL` exact, `DATE` +10 days, description different, category unknown); explicit ties; every candidate `CONSULTATIVE`.
- Jest 5/5 (evidence chips with signed deltas and assistive text, badges, no pre-selection, observable due-date re-sort with selection after re-sort); ESLint clean.
- Code review (BMAD 3 layers): provider key no longer leaves the server; identity comparison case-sensitive; deltas in the tie signature; `CONTAINS` needs ≥ 3 normalized chars and states its direction; punctuation folded; observed holder; zero-padded virtual keys; null-side guard; evidence order asserted on the list; `lowEvidence`, category and persisted-before-virtual asserted on real candidates.

## Out of scope (sibling AXF-140)

Tolerances / completion policy, partial and multi-currency candidates, FX evidence. AXF-17 duplicate suggestion for manual/CSV is a different feature.
