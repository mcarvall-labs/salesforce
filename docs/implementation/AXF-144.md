# AXF-144 — Canonical policy states in the confidence panel

Second slice of AXF-48, stacked on AXF-143 (`aXF_LWC_confidencePanel`,
`ALT_CLS_ConfidencePanelService`, `AXF_CLS_CTRL_ConfidencePanel`). It consumes the basic panel of the
sibling story and applies the canonical forecasting policy states to it; it does not recompute
sources or freshness.

## Components

| Component                                | Role                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_CLS_ConfidencePanelService`         | Gate states are consumed from the policy that declares them (`ALT_CLS_ForecastComparisonService.CONFIDENCE_*`); the local `LEVEL_*` vocabulary is gone. The panel now carries `gatePolicy` (the canonical policy that declares the states and the allowed actions) and `fallbacks` (the fallbacks actually applied while deriving it). |
| `AXF_CLS_CTRL_ConfidencePanel` (AXF-143) | Unchanged: the controller is a passthrough, so the canonical descriptor reaches the LWC untouched.                                                                                                                                                                                                                                     |
| `aXF_LWC_confidencePanel`                | Renders the server state, the policy that declares it, coverage, the fallbacks applied and the gate reason; it computes no state of its own.                                                                                                                                                                                           |

## Rules

- **The vocabulary is consumed, never redeclared.** `INFORMATIVE` / `DEGRADED` / `BLOCKED` are read
  from `ALT_CLS_ForecastComparisonService` (the `AXF-FORECASTING@1.0.0` declaration). No new state
  name, threshold or scoring scale is introduced, and neither side carries a composite score.
- **The declaring policy is named; authority is not claimed.** `gatePolicy` reports the canonical
  policy that declares the states and the allowed actions (`AXF-FORECASTING@1.0.0`), as identity and
  version. It is not presented as "authority", because in the canonical policy authority is evidence
  precedence and this panel carries no evidence-precedence data (see the declared limitation below).
  The identity is reported even when the panel is blocked. The matching policy is not named: it
  declares `CONSULTATIVE` / `PARTIAL` / `RESULT_UNKNOWN` and never `INFORMATIVE` or `DEGRADED`, and
  this panel derives nothing from matching.
- **Fallbacks are reported, never silent.** The panel names the fallbacks it actually applied:
  `FRESHNESS_LIMIT_DEFAULT` when the source declares no freshness limit of its own and the policy
  default (`AXF_CMT_ConfidencePolicy__Default.DefaultFreshnessHours`) was used, and
  `IMPORT_DATE_MISSING` when hand-keyed facts carry no import timestamp and their creation time
  became the recorded success. Only a source that contributes to the derivation registers a
  fallback, so a source excluded by `CUSTODY` — and a panel that ends `BLOCKED` without deriving a
  result — declares none. An empty list means no fallback was needed.
- **The gate reason is always visible.** The reason list is rendered for every non-informative
  state, not only for `BLOCKED`; a `DEGRADED` panel now states why it degraded.
- **`UNKNOWN` stays distinct from a legitimate zero.** A source with no recorded success is
  `UNKNOWN` (never current); a current source with zero facts reports `factCount = 0`. Coverage is
  reported as the included/excluded source counts the server already derives.
- **The UI renders only.** The three canonical states and the permitted actions come from the
  server. The component maps them to a label and a badge variant and maps nothing else; a clean-looking
  row never becomes a state derived on the client, and the component states no fact the response did
  not carry (no "no fallback was needed" on a blocked or older payload, no counts it did not receive).

## Ambiguities and limits

- "Policy/method version" is read as the panel's own policy/method version, already carried by
  `Panel.policyVersion` from `AXF_CMT_ConfidencePolicy__Default`; no separate method version was
  invented.
- "Cutoff" and "evaluation" are the same instant for this panel (`asOf`, the point up to which
  evidence was considered); only one field is exposed rather than two identical ones.
- `gatePolicy` names only the canonical policy that declares these states
  (`AXF-FORECASTING@1.0.0`). It replaced an earlier `policyAuthority` list that also carried
  `AXF-MATCHING@1.0.0`: the matching policy declares `CONSULTATIVE`, `PARTIAL` and `RESULT_UNKNOWN`
  (`6488065.md` lines 36/40/51/54) and never `INFORMATIVE` or `DEGRADED`, and this panel derives
  nothing from matching, so naming it there was a false claim.
- **Declared limitation (open pendency) — AC-2's "authority" is not rendered.** In the canonical
  policy "authority" is evidence precedence: `6520833.md` line 35 states that "higher-authority
  evidence replaces the overlapping lower-authority contribution; it does not add to it", and line
  59 lists `evidence authority` as one of the fields every result records next to the policy
  identity, cutoff, horizon/scenario and confidence state. This panel consumes no evidence-precedence
  data — nothing in `ALT_CLS_ConfidencePanelService` ranks one source's evidence above another's or
  resolves overlapping contributions — so it renders the consumed canonical policy identity and
  version (`gatePolicy`, label "Canonical policy") and claims no authority. Showing a result's
  evidence authority remains pending and needs that precedence data; no value was invented for it.
- The panel has a compile-time reference to `ALT_CLS_ForecastComparisonService` (AXF-137). The
  service no longer references `ALT_CLS_MatchEvidence`; only its test does, to prove the matching
  policy is not claimed. Any environment receiving this change must already carry both classes
  (AXF-137 / AXF-139, both in the same integration branch).
