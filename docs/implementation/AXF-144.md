# AXF-144 — Canonical policy states in the confidence panel

Second slice of AXF-48, stacked on AXF-143 (`aXF_LWC_confidencePanel`,
`ALT_CLS_ConfidencePanelService`, `AXF_CLS_CTRL_ConfidencePanel`). It consumes the basic panel of the
sibling story and applies the canonical Matching/Forecasting policy states to it; it does not
recompute sources or freshness.

## Components

| Component                                | Role                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ALT_CLS_ConfidencePanelService`         | Gate states are consumed from the policies that declare them (`ALT_CLS_ForecastComparisonService.CONFIDENCE_*`); the local `LEVEL_*` vocabulary is gone. The panel now carries `policyAuthority` (canonical policies that authorize the states and actions) and `fallbacks` (the fallbacks actually applied while deriving it). |
| `AXF_CLS_CTRL_ConfidencePanel` (AXF-143) | Unchanged: the controller is a passthrough, so the canonical descriptor reaches the LWC untouched.                                                                                                                                                                                                                              |
| `aXF_LWC_confidencePanel`                | Renders the server state, its authority, coverage, the fallbacks applied and the gate reason; it computes no state of its own.                                                                                                                                                                                                  |

## Rules

- **The vocabulary is consumed, never redeclared.** `INFORMATIVE` / `DEGRADED` / `BLOCKED` are read
  from `ALT_CLS_ForecastComparisonService` (the `AXF-FORECASTING@1.0.0` declaration) and the
  matching policy identity from `ALT_CLS_MatchEvidence`. No new state name, threshold or scoring
  scale is introduced, and neither side carries a composite score.
- **Authority is explicit.** `policyAuthority` names the canonical policies that authorize the
  states and the allowed actions, so an indicator derived from forecasting or matching is explained
  against the policy that owns it rather than against an unnamed local rule. It is a default of the
  result and is reported even when the panel is blocked.
- **Fallbacks are reported, never silent.** The panel names the fallbacks it actually applied:
  `FRESHNESS_LIMIT_DEFAULT` when the source declares no freshness limit of its own and the policy
  default (`AXF_CMT_ConfidencePolicy__Default.DefaultFreshnessHours`) was used, and
  `IMPORT_DATE_MISSING` when hand-keyed facts carry no import timestamp and their creation time
  became the recorded success. An empty list means no fallback was needed.
- **The gate reason is always visible.** The reason list is rendered for every non-informative
  state, not only for `BLOCKED`; a `DEGRADED` panel now states why it degraded.
- **`UNKNOWN` stays distinct from a legitimate zero.** A source with no recorded success is
  `UNKNOWN` (never current); a current source with zero facts reports `factCount = 0`. Coverage is
  reported as the included/excluded source counts the server already derives.
- **The UI renders only.** The three canonical states and the permitted actions come from the
  server. The component maps them to a label and a badge variant and maps nothing else; a stale row
  never turns the server state into a state derived on the client.

## Validation

- AXON_DEV: `ALT_CLS_ConfidencePanelServiceTest` + `AXF_CLS_CTRL_ConfidencePanelTest` — 12/12 pass,
  `ALT_CLS_ConfidencePanelService` 97.5 % covered, `AXF_CLS_CTRL_ConfidencePanel` 81.8 %. The new
  test asserts the canonical states by constant, the authority list, an empty fallback list when the
  source declares its own limit and `FRESHNESS_LIMIT_DEFAULT` when it does not.
- Jest 7/7 for the component: canonical state rendered without recomputation (a `STALE` row under an
  `INFORMATIVE` server state), authority, coverage counts, fallbacks and the gate reason of a
  degraded state.
- No new object, field or permission set. The five added entries are Custom Labels (plus their PT-BR
  translations) for panel text that had no label yet.

## Ambiguities and limits

- "Policy/method version" is read as the panel's own policy/method version, already carried by
  `Panel.policyVersion` from `AXF_CMT_ConfidencePolicy__Default`; no separate method version was
  invented.
- "Cutoff" and "evaluation" are the same instant for this panel (`asOf`, the point up to which
  evidence was considered); only one field is exposed rather than two identical ones.
- `policyAuthority` names both canonical policies because AXF-48's approved course correction
  requires the panel to render the canonical states and explanations of `AXF-MATCHING@1.0.0` and
  `AXF-FORECASTING@1.0.0`. This panel derives nothing from matching today, so the matching identity
  is reported as authority, not consumed as a derivation.
- The panel now has a compile-time reference to `ALT_CLS_ForecastComparisonService` and
  `ALT_CLS_MatchEvidence` (AXF-137 / AXF-139, both in the same integration branch). Any environment
  receiving this change must already carry both classes; they travel together in the sprint branch,
  but not necessarily in a hand-built manifest.
