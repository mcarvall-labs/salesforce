# AXF-125 — Accessible presentation of the consolidated view (desktop/tablet/mobile)

- **Jira:** https://axon-personal-finances.atlassian.net/browse/AXF-125 (parent AXF-1; split from AXF-4)
- **Branch:** `feature/AXF-125-consolidated-presentation` (base `sprint/sprint-4` @ `3fed1d1`).
- **Siblings consumed, not rebuilt:** AXF-122 (`ALT_CLS_ConsolidationService.consolidate` — authorized totals),
  AXF-123 (`reportingIso` / `comparableTotal` / `MISSING_MATERIAL_FX` — the currency comparison),
  AXF-128 (internal counter-entry neutralization), AXF-124 (discard-and-re-derive on a context change),
  AXF-143 (`aXF_LWC_confidencePanel` — the neighbouring panel, whose states are a different derivation).

> **Diff of this pass: one controller, its Apex test, one LWC bundle with its Jest suite, one custom
> tab, 72 Custom Labels with their pt-BR translations, one class access + one tab setting in the
> existing gestor permission set, and one tab entry in the existing application. No new object,
> field, permission set, custom permission or message channel. No production Apex of another story
> was changed.**

## Judgement calls

- **The reporting currency belongs to this surface.** AXF-123 delegates it ("the reporting currency
  is the caller's context (AXF-124/125 own it)"), so the component offers the active presentation
  currencies and starts at the AXF-87 effective preference. A blank value is a first-class choice
  (every total stays in its own currency), which is AXF-122's own contract for a caller that sends no
  `reportingIso` — not a fallback.
- **The `AXF_ContextChanged` payload is not consumed.** `presentationCurrency` is deliberately not
  adopted: the ratified presentation-currency source is the AXF-87 preference, and AXF-124 already
  recorded the same decision for the same payload (`docs/implementation/AXF-124.md`, judgement calls).
  The channel's contract — clear stale state and refetch — is honoured in full, so a context change
  still discards the previous view and re-derives it.
- **The comparable indicator's state is read, not computed.** By AXF-123's own contract the aggregate
  carries no state of its own, so "estimate" is stated when any per-currency row is `ESTIMATED` and
  "same currency" otherwise. Only already-derived values are selected for display; no figure is
  produced in the browser.
- **A withheld indicator names the currency.** `MISSING_MATERIAL_FX` is shown as a reason and the
  statement names the currencies whose `conversionState` is `STALE`/`UNAVAILABLE`. Neither parity nor
  a partial sum is ever presented, and the original totals stay on screen.
- **Per-currency rates and quote instants are not surfaced.** The AC names holders, currency,
  freshness, confidence and exclusions; `rateInflow`/`rateOutflow`/`rateProvider`/`rateEffectiveAt*`
  remain in the DTO for an audit view. Declared below as a limitation rather than quietly dropped.
- **Contributions are not rendered.** The AC does not name them, and the totals plus the holder and
  exclusion lists carry the same decisions; adding a fourth table would be presentation nobody asked
  for.
- **One label per reachable code, with a `|| code` fallback.** Every reason code the service can emit
  (`COVERAGE_UNVERIFIED`, `NO_AUTHORIZED_SCOPE`, `VOLUME_EXCEEDED`, `MISSING_MATERIAL_FX`, the four
  allocation reasons, `ALLOCATION_UNREADABLE`/`AMBIGUOUS`/`INVALID`/`INCOMPLETE`, `UNKNOWN_STATUS`,
  `UNKNOWN_DIRECTION`, the `FIELD_ACCESS:` prefix) and every exclusion reason has a PT-BR label, so no
  raw code reaches a reader; the fallback reproduces the neighbours' `|| code` discipline
  (`aXF_LWC_confidencePanel.js:64-76`).
- **The label/translation containers are not deployed.** See the contract row above: the org already
  carries labels this branch does not, and AXF-135 refused the same deploy for the same reason. The
  branch is the review authority; the org is updated additively.

## Limitations and declared gaps

1. **No rendered-page verification.** The client behaviour is proven by Jest and the derivation by
   Apex; there is no browser, device or screen-reader pass. Tablet/mobile support is the SLDS
   responsive grid plus `slds-scrollable_x` on the tables, which is not the same as a device test.
2. **The tables scroll horizontally on a narrow viewport** (house pattern, `aXF_LWC_confidencePanel.html:117`).
   Nothing is truncated and no value is hidden, but on a phone the reader pans the table.
3. **`lightning-dual-listbox`'s screen-reader behaviour is the platform's.** The component labels it
   and relies on the base component; no accessibility assertion beyond presence can be made in Jest.
4. **No per-currency rate, provider or quote instant** is presented (see judgement calls).
5. **No contribution-level detail** (per source, per holder) is presented.
6. **AXF-32 is still open** (internal transfers). It changes nothing here: this surface derives
   nothing, so a future neutralization rule arrives through the same response untouched.
7. **The app placement is metadata only.** `AXF_CT_ConsolidationPanel` is a tab visible in the gestor
   permission set and listed in the Axon Finance app; no automated check proves the placement renders.
8. **The presentation-currency grant is a decision left with the product.** `AXF_PS_ReportCurrency`
   now grants `customMetadataTypeAccesses` for `AXF_ReportCurrency__mdt`, because without it no
   non-administrator could reach the comparison at all (validation §"A dependency defect"). The
   controller degrades gracefully either way, so the four lines can be reverted without touching this
   story's surface — the effect would be that only administrators can choose a presentation currency.
9. **No automated check of the Apex→LWC serialization boundary.** The DTO annotations are present and
   follow every sibling DTO, but Apex cannot reflect on annotations, `JSON.serialize` ignores them and
   Jest mocks the call, so a future removal would be silent. A static gate would be new tooling for
   one convention and was not built here.
10. **The Apex test does not exercise the description-level labels' runtime values** (see review
    triage, "tests assert label keys"): the org rows were compared against the branch file instead.
